# 架构与服务边界

GoShop 采用“HTTP 聚合层 + 领域微服务 + 基础设施”结构。用户 API 与后台管理端只负责协议转换、认证、授权和聚合，不直接承载跨领域事务或拥有领域数据。

## 服务归属

| 服务 | 唯一数据归属 | 对外职责 |
| --- | --- | --- |
| 用户 | 账号、身份、会话、角色和权限 | 认证、用户资料、RBAC。 |
| 商品 | 商品、分类、品牌、搜索同步事件 | 商品管理与检索。 |
| 库存 | 可售、锁定与调整库存 | 库存扣减、确认和释放。 |
| 订单 | 订单、支付事件、退款请求 | 下单、支付状态与订单生命周期。 |
| 评价 | 评价及评分聚合 | 评价发布、审核和商家回复。 |

## 依赖方向

```text
HTTP API / 后台管理 → gRPC 领域服务 → 各自数据库、缓存与消息依赖
```

聚合层不得绕过领域服务直接访问其数据库；领域服务不得反向依赖 HTTP 控制器。跨服务写操作必须使用明确契约、幂等键和补偿策略。

## 变更守则

1. 新字段先定义数据归属与兼容策略，再修改接口。
2. API 与 Admin 保持薄层；复杂业务下沉到服务层。
3. 所有资源范围字段（组织、门店、团队）必须沿请求链路传播并在数据访问层校验。
4. 数据库迁移应先兼容旧版本，再发布写入端，最后清理旧字段。
