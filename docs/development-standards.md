# 开发规范

## Go 与包设计

- 使用 `gofmt`；标准库、第三方与本地导入分组。
- 包按业务能力拆分，避免 `common`、`util` 成为无边界垃圾桶。
- `context.Context` 为首个参数，不能存入结构体；请求路径不得自行创建 `context.Background()`。
- 生产错误必须返回或处理，不以 `panic` 表达正常失败；错误文本使用小写且不以句号结尾。
- 日志使用结构化字段，不记录密码、令牌、手机号等敏感数据。

## 接口与数据

- `.proto` 是 gRPC 契约源；HTTP 输入输出需保持向后兼容。
- 新字段优先可选；删除字段需经过废弃期和调用方确认。
- 写操作必须具备幂等语义；外部回调要验证签名、时间窗与重放。
- 调用方传入的切片和 map 不得被原地修改，必要时复制。

## 测试与交付

```bash
make format-check
make vet-check
make proto-check
go test ./...
```

涉及真实依赖的改动还应执行对应集成测试。提交说明必须包含变更目的、风险、迁移步骤和回滚方案。
